# Demo Script (5-10 Minute Video Outline)

**Target Audience:** Finance Managers, Auditors, and Engineering Teams.
**Goal:** Showcase the autonomous reconciliation pipeline, deterministic rules engine, LLM explainability, and the strict security safeguards (Maker-Checker, Audit Trails).

## 0:00 - 1:00 | Introduction & Architecture
*   **Visual:** Show the Streamlit Login page.
*   **Talking Points:** Introduce the Autonomous Finance Reconciliation Agent. Briefly mention the tech stack (FastAPI, PostgreSQL, Streamlit, Gemini). Emphasize that the system uses *deterministic Python rules* for identifying financial anomalies, while the LLM is purely used to *explain* the anomaly in human language.

## 1:00 - 2:30 | Role-Based Access & Uploading Data
*   **Action:** Log in as `admin@example.com` (using the password from `.env`).
*   **Visual:** The Dashboard shows total records, current discrepancies, and match rate.
*   **Action:** Navigate to the "Upload & Run" tab.
*   **Action:** Upload the 4 demo CSVs (Orders, DRCs, Payments, Refunds). Point out that the system validates the files synchronously.
*   **Talking Points:** Emphasize CSV injection protection and idempotency (uploading twice won't duplicate data).

## 2:30 - 4:00 | Running the Pipeline & LLM Explanations
*   **Action:** Click "Start Reconciliation Run".
*   **Visual:** Show the run status transition from QUEUED -> IN_PROGRESS -> COMPLETED.
*   **Action:** View the resulting Discrepancies list.
*   **Talking Points:** Expand a discrepancy (e.g., a DUPLICATE_PAYMENT or UNDERPAYMENT). Show the "Why was this flagged?" panel. Highlight that this human-readable explanation was generated by Gemini based on the raw rules engine output.

## 4:00 - 6:00 | The Maker-Checker Safeguard (Key Feature)
*   **Visual:** The Discrepancies screen with an action > $50,000.
*   **Action:** As `admin@example.com` (the user who started the run), attempt to click "Approve" on a high-value discrepancy.
*   **Result:** The UI / API rejects it (`403 Forbidden`).
*   **Talking Points:** Explain the Maker-Checker policy. The "proposer" (the person who ran the reconciliation) cannot approve their own actions. 
*   **Action:** Log out. Log in as `manager@example.com` (Finance Manager).
*   **Result:** The Finance Manager can approve discrepancies < $50,000, but cannot approve the > $50,000 action.
*   **Action:** Log out. Log in as a *different* Admin user (or use a secondary demo account) and successfully approve the > $50,000 discrepancy.

## 6:00 - 7:30 | The Immutable Audit Log
*   **Action:** Log out and log in as `auditor@example.com` (Auditor).
*   **Visual:** Show the UI has hidden the "Approve/Reject" buttons entirely.
*   **Action:** Navigate to the "Audit Log" viewer.
*   **Talking Points:** Show the chronological trace: LOGIN, UPLOAD, RUN_START, RUN_FINISH, ACTION_APPROVED. Explain that this table is protected at the PostgreSQL level by triggers preventing `UPDATE`, `DELETE`, or `TRUNCATE`.

## 7:30 - 8:30 | Conclusion & Scale
*   **Visual:** Show the `docs/DIAGRAMS.md` or architecture diagram on GitHub.
*   **Talking Points:** Briefly recap how the system scales (Background Tasks, PostgreSQL) and how the LLM fallback mechanism guarantees the pipeline never crashes if the AI hallucinates.
*   **Call to Action:** Direct viewers to the GitHub repo and README to run the project locally via Docker.
